# 采购数量与状态约束

> 代码依据：`PurchaseItem`（calculateItemStatus）、`PickupServiceImpl.updatePurchaseInfo`、`QualityServiceImpl.inbound`、`PurchaseServiceImpl.checkCancel`、`PurchaseQcExtension`。

## 一、采购明细数量字段

| 字段 | 含义 | 增加时机 |
| --- | --- | --- |
| purchaseQty | 采购数量 | 下单/变更 |
| pickupQty | 完工数量 | 完工单确认（累计） |
| unDefectiveQty | 良品数 | 质检完成 |
| defectiveQty | 不良品数 | 质检完成 |
| inboundQty | 已入库数量 | 质检入库 |
| returnQty | 采退数量 | 采退出库 |
| cancelQty | 取消数量 | 完结/取消 |

质检扩展（PurchaseQcExtension）：requiredQualityQty（要求质检数）、reworkPendingQty（待返工）、reworkCompletedQty（已返工）、firstInspectPendingQty（待初检）、reInspectPendingQty（待复检）、qualityStage（初检/复检）。

## 二、数量不变式（代码强校验）

1. **完工**：本次完工数 ≤ 待完工数（采购数-已完工），否则报"本次完工数不能大于待完工数"；
2. **返工**：本次返工数 ≤ 待返工数，否则报"本次返工数不能超过待返工数"；
3. **质检入库**：当前入库数 ≤ 最大可入库数 = 良品数+不良品数-已入库数，超出报"入库数量【x】超过最大可入库数量【y】"；每行必须指定库存层级（privateId）；
4. **结单（取消）**：
   - 待返工数=0 且 已返工数=0；
   - 完工数 ≤ 良品数；
   - 无未确认的完工单；
5. **完结时取消数** = 采购数 - 良品数；
6. 免检明细：完工确认后自动把完工数计入良品数并置质检完成（免检级别商品，QualityFreeSpu 控制）。

## 三、明细状态推导（calculateItemStatus）

有效采购数 = 采购数 - 取消数；可入库数 = min(完工数, 良品数)。按以下顺序判定：

1. 取消数 ≥ 采购数 或 有效采购数 ≤ 0 → 已取消；
2. 入库数 ≥ 有效采购数 → 全部已入库（40）；
3. 入库数 > 0 → 部分已入库（30）；
4. 可入库数 ≥ 有效采购数 → 全部可入库（26）；
5. 可入库数 > 0 → 部分可入库（25）；
6. 完工数 ≥ 有效采购数 → 全部完工（22）；
7. 完工数 > 0 → 部分完工（21）；
8. 否则 → 待完工（20）。

主单状态由明细聚合（见 [[采购生命周期与状态机]]）。

## 四、抽检/全检与检验阶段

- **抽检（spotCheck）**：
  - 完工数达到要求质检数、且无良品/返工余量、阶段=初检 → 待初检数=要求质检数；
  - 已返工数达到要求质检数且本次有返工 → 待复检数=要求质检数；
- **全检**：待复检数 += 本次返工数；待初检数 = max(完工数-良品数-待复检数-待返工数, 0)；
- 本次完工含返工数 → 检验阶段切换为复检（RECHECK）。

## 五、质检单入库状态联动

- 良品数合计 = 已入库合计 → 质检单=完全入库（15），入库状态=完全入库；
- 良品数合计 > 已入库合计 → 部份入库（10）；
- 入库成功后同步：生成采购入库单（自营仓走 WMS）、更新采购明细入库数、生成财务凭证（非自营仓）、写备货追踪、刷新质检超期提醒。
