# 采购生命周期与状态机

采购主单使用 `purchase_status`，采购明细使用 `purchase_item_status`；二者复用同一状态编码。草稿到审核阶段由主单操作直接同步，进入待完工后，明细数量与明细状态是主单状态的主要依据。

## 已确认的主链

```text
草稿(0)
  → 提交 → 审核中(5)
  → 审核同意 → 已审核/待下单(10)
  → 订金零比例处理或付款回调 → 待完工(20)
  → 完工数量增加 → 部分/全部完工(21/22)
  → 良品数量形成可入库量 → 部分/全部可入库(25/26)
  → 入库数量增加 → 部分/全部已入库(30/40)
```

审核拒绝会从审核中回到草稿；待下单状态在不存在未作废订金应付单时可以反审核回草稿；草稿删除实际改为作废 `-1`。

## 状态的数量口径

对已进入待完工及后续阶段的采购明细：

- 有效采购量 = `purchaseQty - cancelQty`。
- 可入库量 = `min(pickupQty, unDefectiveQty)`。
- `inboundQty` 优先决定已入库状态，其次是可入库量，再次是完工量。
- `cancelQty >= purchaseQty` 时明细为已取消 `-2`。

明细状态由 `PurchaseItem.calculateItemStatus()` 重算；采购主单由 `PurchaseService.calculateAndUpdatePurchaseStatus(purchaseId)` 聚合有效明细状态。聚合优先级为：已入库 > 可入库 > 完工 > 待完工。全体有效明细达到同一完整阶段时，主单进入完整状态；任一明细处于部分阶段时，主单进入对应部分状态。

## 直接状态操作

- 创建：主单和明细均为草稿。
- 提交、审核、审核拒绝、反审核：`PurchaseServiceImpl` 同步写主单与全部明细。
- 完工确认：`PickupServiceImpl.updatePurchaseInfo` 累加 `pickupQty` 后重算明细与主单。
- 质检报告导入：`QualityServiceImpl.updatePurchase` 更新良品/不良品后重算明细与主单。
- 采购入库尾款处理：`FinalPaymentPayableStrategy` 更新 `inboundQty` 后重算明细与主单。
- 截单/红字订金：`DepositRedPayableStrategy` 更新 `cancelQty` 后重算明细与主单。

## 重要限制

数量变化不会自动改变状态。调用方必须同时执行明细状态重算和主单聚合；只更新数量字段会造成状态滞后。
