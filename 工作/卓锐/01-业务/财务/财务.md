# 财务（FMS）

财务由 `xzy-fms` 服务承担：应付单管理、付款申请审批、付款单、预付款与勾稽、待请款管理。数据来源主要是 PMS（采购应付策略生成的来源数据），最终对接银行付款。

> 本文档 2026-09-04 基于 `xzy-erp-public/xzy-fms` 源码重新梳理，替代旧版。

## 核心对象

| 对象 | 模型 | 职责 |
| --- | --- | --- |
| 应付来源 | AccountPayableSource | PMS 策略/汇总写入的来源数据，未被汇总任务消费前保持未汇总状态 |
| 应付单 | AccountPayable / Item | 暂存→生效→完结；-1 作废；付款链的起点 |
| 付款申请单 | ZrPayApply / Item | 多级审批：待提交→部门负责人→供应链BP1→BP2→未申请付款→部份/全部申请付款→已全部付款；-1 作废 |
| 付款单 | ZrPay / Item / Log | 未付款→部分付款→全部付款；-1 作废 |
| 预付款单 | PrePayment / Item | 新建→待审核→待付款→部分付款→已付款；-1 作废（可恢复生效） |
| 请款单（旧链路） | PayApply / Item | 已请款未提交→待付款→部分付款→已付款 |
| 付款单（旧链路） | PayBill / Record | 待付款→部分付款→已付款 |
| 待请款 | WaitingPayment / Item | 未请款→已请款；类型：采购尾款 |
| 勾稽 | PayApplyCrossCheck | 请款单与预付款的勾稽记录（占用/已用/未用勾稽金额） |

## 业务类型口径

- 付款申请类型（ZrPayApplyTypeEnum）：0 采购尾款 / 5 采购定金 / 10 采购完结 / 15 采购退货 / 100 其他费用 / 101 结算调整；
- 单据业务类型（BillBusinessTypeEnum）：1 预付款单 / 2 请款单 / 3 付款单；
- 勾稽类型（CrossCheckTypeEnum）：预付款。

## 两条付款链路

```text
新链路（卓锐应付）：
PMS策略生成来源数据 → 汇总任务(每日0:30, 按 供应商+采购单+业务日期+应付类型 汇总)
  → 应付单(暂存→生效) → 付款申请单(三级审批) → 付款单(付款) → 应付完结

旧链路：
预付款单(审核通过→生成付款单) → 付款
待请款(采购尾款) → 请款单(可勾稽预付款) → 付款单 → 付款
```

## 并发控制

- 应付单级锁 `ACCOUNT_PAYABLE_LOCK_KEY+id`（确认/作废/反审/生成下游）；
- 付款单全局锁 `PAY_PRE`；
- 请款单按 供应商+币种+采购单等维度生成锁键；
- 汇总任务全局锁（等待 5s/持有 600s，上次未完成则跳过）。
