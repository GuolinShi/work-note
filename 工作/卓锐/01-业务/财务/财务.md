# 财务（FMS）

财务由 `xzy-fms` 服务承担，负责应付账款、付款申请、付款单与付款记录，并与 PMS 采购流程联动（订金、尾款、完结、退货的回调与回写）。

## 核心对象

| 对象 | 表/模型 | 职责 |
|---|---|---|
| 应付来源 | AccountPayableSource | 业务事件（采购单等）产生的原始应付明细，汇总后生成应付单 |
| 应付单 | AccountPayable / Item | 应付账款主单，可确认生效、作废、反审，向下游生成付款申请/付款单 |
| 付款申请 | ZrPayApply / Item | 付款申请单，经部门/供应链 BP 两级审核后进入付款环节 |
| 付款单 | ZrPay / Item | 付款执行载体，付款金额按记录推进 |
| 付款记录 | ZrPayLog | 每笔付款流水（单号、金额、付款信息） |
| 请款单/付款单/预付款/待付款 | PayApply / PayBill / PrePayment / WaitingPayment | **旧付款链路单据，页面已确认未使用**（见废弃提示） |

## 系统边界

- 上游：PMS 采购（订金/尾款/完结/退货产生应付与付款申请需求）、WMS（入库/出库状态联动）、SRM。
- 下游回调：付款申请创建/审核后回调 PMS 采购单（已申请订金、完结状态）与采购入库/退货单（已完成）。
- FMS 不直接写 PMS/WMS 数据表；跨服务通过 Feign（remotePurchaseService 等）回调。

## 流程总览

```text
业务事件 → 应付来源(AccountPayableSource)
  → 汇总生成应付单(AccountPayable，暂存)
  → 确认生效(5)
  → 生成付款申请(ZrPayApply) / 生成付款单(ZrPay)
付款申请：提交 → 部门负责人审核 → 供应链BP1审核 → 供应链BP2审核 → 未申请付款 → 申请付款 → 已全部付款
付款单：付款记录(ZrPayLog) → 部分付款/全部付款 → 回写应付单完结(10)
```

## 废弃链路提示（读取代码时先跳过）

用户已确认（2026-08-12）：`views/fms/payApply`、`views/fms/payBill`、`views/fms/prePayment` 三个页面目录未在生产使用，对应旧"请款单→付款单→预付款→待付款"链路（PayApply/PayBill/PrePayment/WaitingPayment）**不要当作当前业务流程**。请先对照 [[前端FMS废弃接口清单]]：

- 旧链路后端服务与枚举仍在（PayApplyStatusEnum、PayBillStatusEnum、PrePaymentStatustEnum、WaitingPaymentStatusEnum、BillBusinessTypeEnum、CrossCheckTypeEnum），但前端无入口。
- PayApplyCrossCheck（请款勾稽）仅有后端实现，前端无调用。
- 当前活跃链路是：应付账款（accountPayable）→ ZrPayApply（付款申请）→ ZrPay（付款单）→ ZrPayLog（付款记录）。
