# 应付与付款流程

> 代码依据：`AccountPayableServiceImpl`、`AccountPayableSummaryJob`、`ZrPayApplyServiceImpl`、`ZrPayServiceImpl`、`PrePaymentServiceImpl`、`PayApplyServiceImpl`、`PayBillServiceImpl`。

## 一、应付单（AccountPayable）

状态：0 暂存 → 5 生效 → 10 完结；-1 作废。

### 1. 生成
- 来源：PMS 应付策略（订金正向/订金红字/尾款/结算调整红字）写入来源数据；
- **自动汇总任务**（accountPayableSummaryJob，每日 0:30）：
  - 汇总维度：供应商 + 采购订单 + 业务日期 + 应付类型；
  - 多线程并行汇总，生成应付单并回写来源数据汇总状态；
  - 全局锁保护，上次未完成则跳过本次。

### 2. 确认（confirm）
- **仅暂存可确认**；加应付单锁；
- 防御校验：若已挂付款申请单/付款单则检查下游单据存在性（防手工改库导致的数据不一致）；
- 确认后置生效。

### 3. 作废（cancel）
- **仅暂存可作废**；
- **订金应付单作废 → 回写采购单**：订金申请标记置 N、订金状态回未申请（2026-04-21 起）；
- 生效后的应付单不能直接作废（需走红字冲销）。

### 4. 反审核（reverse）
- **仅 其他费用/采购订金 类型允许反审**；
- **仅生效状态可反审**；
- 下游约束：付款申请单状态必须为空或作废、付款单状态必须为空或作废，否则不可反审；
- 反审后回暂存。

## 二、付款申请单（ZrPayApply，新链路）

状态机：0 待提交 → 5 部门负责人审核 → 7 供应链BP1审核 → 9 供应链BP2审核 → 10 未申请付款 → 15 部份申请付款 → 20 全部申请付款 → 40 已全部付款；-1 作废。

### 1. 生成（从应付单发起，addPayApply）
- 勾选应付单（必须同口径可合并，`checkComplex` 校验）；
- **应付单必须没有未作废的付款申请单**，否则报"应付单存在未作废的付款申请单"；
- 全部应付单加锁后：生成付款申请单（单号前缀付款申请）+ SKU 明细；勾选"直接提交"则状态=部门负责人审核；
- 回写应付单的付款申请单号与状态。

### 2. 提交（submit）
- 仅待提交可提交 → 部门负责人审核；同步回写应付单。

### 3. 审批（audit，按节点 node 区分）
- **节点状态强校验**：部门负责人节点只接受"部门负责人审核"状态的单；BP1 只接受"供应链BP1审核"；BP2 只接受"供应链BP2审核"；
- 逐级通过：部门负责人→BP1→BP2→未申请付款；
- **任一节点拒绝 → 回待提交**；
- 每次状态变化回写所有关联应付单的付款申请状态。

### 4. 作废（cancel）
- **仅待提交可作废**；
- **采购完结类型不允许作废**；
- 尾款类型作废 → 回写 PMS 财务入库凭证状态（回未申请付款）；
- 退货类型作废 → 回写 PMS 财务出库凭证状态；
- 回写应付单付款申请状态=作废。

## 三、付款单（ZrPay）

状态：0 未付款 → 5 部分付款 → 10 全部付款；-1 作废。

### 1. 新增（add）
- 从付款申请单组装付款数据（getPayData）；
- 付款明细不能为空；总金额=明细合计；已付金额初始 0；
- 生成付款单号，回写付款申请单明细的付款单号（itemStatus=Y），回写应付单付款状态。

### 2. 付款
- 按付款记录（ZrPayLog）逐笔登记，累计已付金额；
- 已付=总额 → 全部付款；部分支付 → 部分付款；
- 付款状态同步回写付款申请单与应付单。

### 3. 删除/作废
- 删除：**仅未付款可删除**（"付款单已经付款，不能删除！"），删除后应付单付款状态回作废；
- 作废：仅未付款可作废；清空付款申请单明细上的付款单号（itemStatus=N），应付单状态回作废。

## 四、预付款单（PrePayment，旧链路）

状态：0 新建 → 1 待审核 → 2 待付款 → 3 部分付款 → 4 已付款；-1 作废（可恢复）。

- **新增/编辑**：按采购单申请预付金额；编辑时校验 **该采购单累计申请预付 + 已请款金额 ≤ 采购金额**，超出报"采购单总付款金额与该笔预付款单金额之和超过采购金额，无法申请付款！"；
- **提交**：仅新建可提交；必须维护银行信息；同样执行金额上限校验 → 待审核；
- **审核**：仅待审核可审核；通过→待付款并 **自动生成付款单（PayBill，业务类型=预付款单）**；拒绝→回新建；
- **作废/恢复**：仅新建可作废；作废状态可恢复为新建（recover）；
- **勾稽额度**：预付款金额 - 占用勾稽金额（请款单状态 0/1）- 已用勾稽金额（状态 2/3）= 未用勾稽金额。

## 五、请款单（PayApply，旧链路）

状态：0 已请款未提交 → 1 待付款 → 2 部分付款 → 3 已付款。

- **生成前提**：待请款（WaitingPayment，采购尾款，未请款状态）必须来自 **同一采购单**（"请选择相同采购单下的待请款单"）；
- **新增校验**：
  - 明细非空；必须选择供应商银行；
  - 有勾稽需求时：供应商必须存在可勾稽的同币种预付款单；本次勾稽金额 ≤ 未用勾稽金额；
  - 该采购单存在可用勾稽额度时，勾稽对象必须选中这些预付款单（"该采购单存在可用勾稽金额不为0的预付款单，请重新选择确认"）；
  - **请款金额 ≥ 勾稽金额**；
- 加锁保存后：待请款状态→已请款；
- **删除**：仅"已请款未提交"状态可删除，删除后待请款回未请款。

## 六、付款单（PayBill，旧链路）

状态：0 待付款 → 1 部分付款 → 2 已付款。
- 预付款审核通过自动生成；请款单提交后进入付款；
- 付款（pay）：本次付款金额不能超过未付金额，逐笔登记付款记录（PayBillRecord）；
- 删除：按状态边界校验。

## 七、边界汇总

| 单据 | 关键边界 |
| --- | --- |
| 应付单 | 仅暂存可确认/作废；反审仅限其他费用/订金且下游必须已作废 |
| 付款申请单 | 三级审批节点状态强校验；拒绝回待提交；完结类型不可作废 |
| 付款单 | 未付款才可删除/作废；付款超额被拒 |
| 预付款 | 预付+请款 ≤ 采购金额；银行必填；作废可恢复 |
| 请款单 | 同一采购单；勾稽金额 ≤ 未用额度；请款 ≥ 勾稽 |
| 联动 | 付款申请/付款状态变化均回写应付单；作废回写 PMS 凭证状态 |
