# RMA 售后流程

> 代码依据：`RmaServiceImpl`、`RmaRefundServiceImpl`、`RmaReturnServiceImpl`、`RmaRedeliveryServiceImpl`。
> RMA（Return Merchandise Authorization）= 售后主单，一张 RMA 可组合三种子流程：退款、退货、重发（三位二进制标记，共 7 种组合）。

## 一、RMA 类型与状态

**类型（RmaTypeEnums）**：退款(100)、退货(010)、重发(001)，可任意组合（如 111=退款+退货+重发）。

**主单状态（RmaStatusEnums）**：
| code | 状态 | 说明 |
| --- | --- | --- |
| 1 | 草稿 | 手动创建/平台同步后的初始态 |
| 2 | 待审核 | 线下单提交后 |
| 3 | 待处理 | 审核通过，子流程生成/执行中 |
| 4 | 已完成 | 所有子流程完成或取消（终态） |
| 5 | 已取消 | 全部子流程取消（终态） |

**子流程状态**：
- 退款（RmaRefundStatusEnums）：草稿→待审核→待退款→退款完成/已取消；
- 重发（RmaRedeliveryOrderStatusEnums）：跟随重发产生的 C 端订单状态聚合（待发货/部分发货/已发货/已完成等）；
- 退货：状态来自 WMS 退件单（ReturnStatusEnum），按退件单号回写。

**来源（RmaSourceTypeEnums）**：API 同步 / 手动创建。

## 二、创建（addOrEdit）

手动创建校验（边界）：
- 客户申请时间不允许超过当前时间；
- 平台 RMA 单号在同一店铺内唯一（有平台单号时）；
- **关联订单校验**：按平台原订单号找系统订单，只有 **正常销售订单且状态 ∈ {已发货, 已取消, 已完成}** 可作为 RMA 源单；没有满足条件的订单 → 报"不存在支持发起RMA的系统订单"；
- 含退款：退款信息必填；线下打款方式必须收款账户信息完整；实退金额创建时置空；
- 含退货：退货明细必填；每个退货行必须挂在通过校验的源订单上，否则报"订单必须是正常销售订单，且状态为已发货、已取消或已完成"；
- 含重发：重发信息必填。
- 初始：来源=手动，状态=草稿。

## 三、提交（submit）与审核（audit）

**提交**（仅线下单）：
- API 同步的 RMA 不允许手动提交（"只有线下RMA可以提交"）；
- 仅草稿可提交；
- 提交前计算信息完整性与标签（见第六节）；状态→待审核。

**审核**（仅线下单）：
- API 同步单不允许审核；仅待审核可审；
- 拒绝：必须填写拒绝原因，退回草稿；
- 通过：进入 **生成子流程**（doGenChildFlow）。

## 四、生成子流程（doGenChildFlow）

- RMA 已是终态 → 不生成；
- 状态置 **待处理**；按类型位依次生成：
  1. **退款**：先生成退款单（生成退款单号，前缀 SALES_RMA_REFUND_PRE）；
     - 线下打款 → 退款单进入待审核（走退款单审核，通过后待退款）；
     - 平台退款 → 按平台流程标记；
  2. **完整性检查**：`checkItemSellerSku` —— RMA 所有明细必须能映射到系统 SKU（RmaSysItem 非空）；不完整则维持状态等待补全（打 SELLERSKU_MATCH_ERROR 标签），不生成退货/重发；
  3. **重发**：生成重发记录并 **创建一张 RMA 属性的 C 端订单**（订单属性=3，状态待审核），该订单走正常审单发货链路，但 **不参与自动拆单/自动分仓**；重发单状态随该订单状态聚合刷新（见 updateRmaRedeliverStatus）；
  4. **退货**：退货行信息完整（仓库+跟踪号都有）→ 调 WMS `saveReturn` 创建退件单（来源=RMA，回写退件单号 returnNo）；仓库不存在则报错。
- 每次子流程变化后 `maintainRmaStatus` 重算主单状态。

## 五、子流程执行与回写

### 退款
- 草稿可提交（非草稿报"非草稿状态不能操作"）；
- 待审核可审核：通过→待退款；拒绝（必须填意见）→退回草稿；
- 待退款 → 标记退款（markRefund）→ 退款完成（状态边界：非待退款不允许标记）；
- 金额折算：申请金额按当月汇率折算 RMB 与 USD（汇率取不到报"获取币种汇率失败"）；
- 取消：仅可取消状态允许（`canBeCancelled`），取消后联动刷新主单状态。

### 退货（与 WMS 联动）
- SMS 侧保存退货行（仓库、跟踪号、原因、产品快照）；
- 审核通过后推 WMS 创建退件单（见上）；
- WMS 退件单回写两个接口：
  - `updateReturnInfo`：回写退件数量（实收/良品/不良品）到 RMA 退货行的 products 快照；
  - `updateReturnStatus`：回写退件状态与完成时间，随后 `checkAndUpdateFinishStatus` 重算 RMA 完成状态。

### 重发
- 重发订单（C 端 RMA 属性单）的任何状态变化（审单/截单/发货/取消/拆单）都会触发 `updateRmaRedeliverStatus`：
  - 按 sourceCode 找全部关联订单；若发生过拆单，只统计子单；
  - 全部终态 → 重发完成；实发数=已发货数 → 已发货；部分发货 → 部分发货；否则待发货；
  - 拆单时同步更新重发展示单号（多个子单号）。

## 六、信息完整性与标签（checkRmaInfoCompleteAndCalRmaTags）

| 检查项 | 不完整时标签 |
| --- | --- |
| 明细 sellerSku 全部映射到系统 SKU | SELLERSKU_MATCH_ERROR |
| 退货行都有退件仓库 | NO_RETURN_WAREHOUSE |
| 退货行都有跟踪号 | NO_TRACKINGING_NUMBER |
| 退款申请金额>0 | （金额不完整，不打标签） |
| 重发收件人/国家/电话/城市/币种/地址齐全 | NO_REDELIVERY_INFO |

全部满足 → completeFlag=Y。

## 七、完成判定（calRmaCompleteStatus）

- **全部子流程完成**（完成或取消均算完成）→ RMA 已完成；
- **全部子流程取消** → RMA 已取消；
- 退款：有退款单号且状态为完成/取消才算结束；
- 退货：所有退货行都有退件单号且状态均为终态；
- 重发：重发订单号存在且关联订单全部终态。

## 八、取消（deleteById）

- **状态边界**：只有草稿/待审核/待处理可取消（终态不行）；
- **来源边界**：API 同步的 RMA 不支持手动取消；
- 草稿/待审核：直接取消主单（重发订单若已生成则一并取消）；
- 待处理：按顺序取消 退款 → 重发 → 主单 → 退货（退货最后取消，因为跨服务调 WMS）；
- 退货取消：已生成退件单的记录退件单号待调用退件取消接口（代码中为 TODO）。

## 九、边界汇总

- RMA 源单只能是销售订单且处于已发货/已取消/已完成；
- API 同步单不走提交/审核，直接由系统推进子流程；
- sellerSku 映射不完整会阻塞退货/重发生成，但不阻塞退款；
- 重发订单是真实 C 端订单（占库存、走发货），但跳过自动拆单分仓；
- 主单状态完全由子流程状态推导，不直接修改。
