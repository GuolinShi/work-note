# 截单与取消流程

> 代码依据：`chain/order/cutoff/*`、`chain/shiporder/cutoff/*`、`chain/order/cancel/*`、`OrderServiceImpl.cutOff/doCutOff/cancel/cancelWithoutCheck`。
> 截单（拦截）= 订单已流转后，因平台退款/取消/信息更新或人工原因，把订单从发货流程中拦回来。

## 一、截单统一入口（cutOff）

`OrderServiceImpl.cutOff(CutOffContext)`：
- 订单 **没有发货通知单** 且状态 ∈ {草稿, 待审核, 问题件}（`canOrderCut`）→ 直接走订单级截单链（`doCutOff`）；
- 否则（已有发货通知单，通常是待发货）→ 走发货通知单截单链（`orderShipService.cutOff`）。

截单上下文必填：orderId + 截单类型（CutTypeEnums）；可选：原因、客服备注、截单来源（AUDIT=审单触发）。
手动截单入口（界面）固定使用 MANUAL 类型。

## 二、订单级截单链（CutChain）

### A. 前置（PreCut）
- 上下文校验（订单/类型非空），否则"截单订单检查错误"；
- 加载订单；若已有发货通知单号则一并加载；
- **状态边界**：`canCut`（草稿/待审核/待发货/问题件），否则"订单状态不支持截单"。

### B. 订单截单处理（OrderCut）——按原状态分两条路

**B1. 原状态 ∈ {草稿, 待审核, 问题件}（cutOff1）**
- **类型边界**：只允许 退款完成/退款中/部分退款/未付款取消/旺店通截单/审单库存截单，其它类型记错误日志后直接返回（不改单）；
- 标签维护：退款完成/未付款取消 会移除"退款中/部分退款"标签，再加上本截单类型对应标签；
- **来源=审单（AUDIT）** → 订单状态改为 **问题件**；其它来源不改状态（等后续取消链处理）；
- 记日志并刷新 RMA 重发状态。

**B2. 原状态=待发货（cutOff2）**
此时截单结果来自发货通知单链（WMS 拦截）：拦截中/拦截失败/拦截成功。
- 拦截成功：清空仓库单号、清空发货通知单号，订单转 **问题件**；
- 标签：拦截中→加"拦截中"；拦截失败→移除"拦截中"加"拦截失败"；拦截成功→移除两者并加截单类型标签；
- 拦截失败原因默认文案："订单拦截申请在WMS已存在订单已出库待发货，待仓库同事确认是否可以库内截回"。

### C. 取消联动（OrderCancel）
截单成功 且 截单类型可取消（退款完成/未付款取消/旺店通）且 来源不是审单 → 继续走取消链（正常取消），日志"同步平台订单状态更新为已取消"。

### D. 释放库存（ReleaseStock）
- 截单成功 且 原状态=待发货 且 非代发单 → 调 WMS `releaseInventory`（ORDER_RELEASE）释放占用；
- **重新锁定**：原订单曾锁过单（lockTime 非空）且截单类型=合单影响/手动截单 → 重新 `lock` 排队占库存。
  - 原因：部分退款导致 SKU 变化的订单会在 orderChange 里重新锁单；界面手动截单可无脑重新锁定。

## 三、发货通知单级截单链（ShipCutChain）

用于订单已有发货通知单（通常是待发货，可能已推送三方仓）。

### A. 前置（PreShipCut）
- 通知单必须存在；
- **状态边界**：通知单必须是待发货，否则"发货通知单不是待发货，不允许截单"。

### B. 取消三方仓出库单（CancelWarehouseCut）
- 已推送（pushFlag=是）且有仓库单号：
  1. 先查三方仓出库单状态（查询失败/超时 → 抛异常"查询海外仓出库单状态服务异常或超时"，等待重试）；
  2. 三方仓状态已是已取消 → 截单成功；
  3. 否则调取消接口：接口失败/超时 → 抛异常；接口返回错误信息 → 截单失败（除非截单原因包含"已取消"，按成功处理——双重保险）；
- 未推送或无仓库单号 → 直接截单成功。

### C. 取消发货通知单（ShipOrderCancelCut）
- 截单成功 → 通知单状态置 **已取消**。

### D. 回写订单（OrderCut）
- 遍历通知单关联的所有源订单（合单场景有多个）：
  - 发起截单的那个订单按原截单类型处理；
  - **其它源订单一律按 MERGE_AFFECT（合单影响）类型** 走订单级截单（释放库存、重新锁定、转问题件等）。

## 四、取消链（CancelChain）

入口：
- 界面取消（`cancel(OrderCancelReq)`）：cancelType=正常取消，开启平台状态校验（orderStatusCheck=true）；
- 截单联动取消：不开启平台状态校验（因为平台状态已在截单阶段确认）。

### A. 前置（PreCancel）
- ctx 校验（orderId+cancelType 必填）；
- **状态边界**：`canCancel`（草稿/待审核/问题件），否则抛"订单状态不支持取消"。
- 注意：待发货订单不能直接取消，必须先截单（拦截库存/三方仓）成功后由系统取消。

### B. 平台状态校验（PlatformStatusCheck）
- 仅线上单且开启校验时执行；人工单跳过；
- 从 Mongo 查最新平台状态：只有平台状态映射为 退款完成/未付款取消 才允许取消，否则抛"平台订单不是已取消，不支持取消订单"。

### C. 锁库存释放（InventoryWaitCancel）
- lockFlag=Y → `unlock`（删除锁定明细、释放已占库存、清除锁定时间）。

### D. 取消落库（UpdateOrder → cancelWithoutCheck）
- 状态置 **已取消**，记录取消类型；追加截单标签；取消原因拼入客服备注；
- 记操作日志；刷新 RMA 重发单状态。

取消类型（OrderCancelTypeEnums）：1 正常取消、2 拆单取消（拆单后原单无剩余）、3 合单取消（合单后原通知单作废）。

## 五、边界汇总

| 场景 | 行为 |
| --- | --- |
| 草稿/待审核/问题件 + 平台退款/取消 | 截单（转问题件或不改状态）→ 可取消类型继续置已取消 |
| 待发货 + 平台更新/退款 | 先请求 WMS/三方仓拦截：成功→清单号转问题件→释放库存；失败→保持待发货+拦截失败标签，等仓库确认 |
| 拦截中 | 订单带"拦截中"标签，等待三方仓回调（同步任务 SyncFromWarehouseJobHandler 跟进） |
| 审单触发的截单 | 一律转问题件，不直接取消（库存问题需人工看） |
| 合单子单被截 | 其它子单按"合单影响"连带截单 |
| 已发货/已取消/已完成 | 不支持截单；平台更新只更新有限费用字段（Shopee/Amazon） |
| 人工取消 | 需平台状态确为取消态（线上单），防止误取消在途订单 |
