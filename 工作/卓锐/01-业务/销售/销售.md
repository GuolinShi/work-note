# 销售（SMS）

销售由 `xzy-sms` 服务承担，负责多平台销售订单（C 端）的接入、自动提交、拆单分仓、审单、锁库存、截单/取消、发货通知、合单、推仓/标发，以及 RMA 售后（退款/退货/重发）与 B 端订单（PI 单）。

> 本文档 2026-09-04 基于 `xzy-erp-public/xzy-sms` 源码重新梳理，不沿用旧知识库结论。

## 支持的销售平台（按解析器）

代码中的订单解析处理器（`handler/order/resolve`）：Amazon、eBay、Shopify、Wayfair、TikTok、Lazada、Shopee、Rakuten、鲸汇（JingHui，platformId=99，ERP 对接商）。每个平台一个 `OrderHandle` 扩展实现，按 `platformId` 作为 BizScene 分发。

## 核心对象

| 对象 | 模型 | 职责 |
| --- | --- | --- |
| 销售订单 | Order / OrderItem / OrderItemSon | C 端订单主单；OrderItem 是平台 sellerSku 明细，OrderItemSon 是映射后的系统 SKU 明细 |
| 订单地址 | OrderAddress | 收件人信息 |
| 订单费用 | OrderCost / OrderItemCost | 订单/明细维度的金额（成交额、优惠、税、其它收入等） |
| 发货通知单 | OrderShip / OrderShipItem / OrderShipAddress | 审单通过后生成，是推仓/发货/合单的载体 |
| 订单锁定 | OrderLock | 锁库存明细（按 SKU 记录应锁/已锁/未锁数量） |
| 锁单记录 | （订单字段 lockFlag/lockTime） | lockFlag=Y 表示锁定中；lockTime 记录首次锁定时间（决定占用顺序） |
| RMA | Rma / RmaItem / RmaSysItem / RmaRefund / RmaReturn / RmaRedelivery | 售后主单 + 退款/退货/重发三个子流程 |
| B 端订单 | TobOrder / TobOrderItem / TobOrderAddress | PI 单，审核后生成对应 C 端订单 |
| 基础资料 | Platform / Shop / Listing / SellerSku / Customer | 平台、店铺、刊登、卖家 SKU 映射、客户 |
| 规则 | AutoAuditRule / AutoRuleItem / AutoWhRule | 自动审单规则、自动分仓规则 |
| 解析失败记录 | OrderResolveFailRecord | 鲸汇订单占用库存/出库/释放库存失败的补偿记录 |

## 订单状态机（OrderStatusEnums）

| code | 状态 | 说明 |
| --- | --- | --- |
| 1 | 草稿（WAIT_SUBMIT） | 未支付/不完整/待自动提交 |
| 2 | 待审核（WAIT_AUDIT） | 已提交，等待人工或自动审单 |
| 3 | 待发货（WAIT_DELIVERY） | 审单通过，已占用库存，等待仓库发货 |
| 4 | 已发货（DELIVERED） | 仓库已发货（或虚拟订单审单后直达） |
| 5 | 问题件（WRONG） | 审单/截单过程中发现异常，需人工处理 |
| 6 | 已取消（CANCELLED） | 终态 |
| 7 | 已完成（FINISHED） | 终态 |

状态动作许可（`OrderStatusEnums` 静态方法，是所有流程的边界基准）：

| 动作 | 允许状态 |
| --- | --- |
| canEdit（编辑） | 草稿、待审核、问题件 |
| canSplit（拆单） | 草稿、待审核、问题件 |
| canAudit（审单） | 待审核、问题件 |
| canLock（锁库存） | 待审核、问题件 |
| canCancel（取消） | 草稿、待审核、问题件 |
| canOrderCut（订单级截单） | 草稿、待审核、问题件 |
| canCut（含发货通知单截单） | 草稿、待审核、待发货、问题件 |
| canSend（发货） | 仅待发货 |
| ignoreUpdate（忽略平台更新） | 已发货、已取消、已完成 |

## 订单步骤（OrderStepEnums，自动提交进度）

| code | 步骤 | 说明 |
| --- | --- | --- |
| 0 | INIT | 初始（人工创建的 C 端线下单手动提交前停留在此） |
| 10 | MIXED_SPLIT | 待混仓拆单 |
| 20 | AUTO_WH | 待自动分仓 |
| 100 | SUBMIT | 待提交完成（直发单分仓后/代发单跳过分仓） |
| 101 | FINISH | 结束 |

## 发货方式（OrderShippingTypeEnums）

- 1 直发（OWN_SEND）：自营仓发货，走完整审单+锁库存+推仓链路。
- 2 代发（ISS_SEND）：平台仓/第三方代发，跳过自动分仓，不锁库存，审单不发通知单（按平台仓状态流转）。
- 3 混仓（MIXED_SEND）：同一订单既有直发 SKU 又有代发 SKU，自动提交阶段拆成两张子单。

## 订单属性（OrderAttributeEnums）

1=C 端正常销售订单，2=样品/赠品订单，3=RMA 单（重发生成），4=B 端正常销售订单。
自动合单只对属性=1 的发货通知单生效；RMA 属性订单不参与自动拆单/分仓。

## 关键标志位

| 标志 | 枚举 | 含义 |
| --- | --- | --- |
| pushFlag | PushFlagEnums | 发货通知单推仓状态：0 未推送 / 1 已推送 / 2 无需推送（未对接仓库） |
| mergeFlag | MergeFlagEnums | 合单状态：0 未执行合单 / 1 已执行合单 / 2 无需合单 |
| signFlag | SignFlagEnums | 标发状态：0 未标发 / 1 已标发 / 2 无需标发 |
| lockFlag | Order.lockFlag | Y=锁库存中 |
| completeFlag | Rma.completeFlag | RMA 子流程信息是否完整 |

## 截单类型（CutTypeEnums）

| 类型 | 触发场景 | 附带标签 |
| --- | --- | --- |
| MANUAL | 界面手动截单 | - |
| SYNC_EXT_WAREHOUSE | 系统截单（同步三方仓状态异常） | 仓储物流异常 |
| PUSH_EXT_WAREHOUSE | 系统截单（推送三方仓失败） | 仓储物流异常 |
| MERGE_AFFECT | 系统截单（合单受其它子单更新/退款影响） | - |
| API_UPDATE | 系统截单（三方平台信息更新） | 平台信息更新 |
| REFUNDING | 系统截单（退款中） | 退款中 |
| REFUNDED | 系统截单（退款完成） | 退款完成 |
| UNPAID_CANCEL | 系统截单（未支付取消） | 未付款取消 |
| PARTIAL_REFUND | 系统截单（部分退款） | 部分退款完成 |
| WDT | 旺店通截单 | - |
| AUDIT_INVENTORY | 审单库存问题截单 | - |
| AUDIT_EXT_STATUS | 平台状态校验问题截单 | - |

其中 REFUNDED / UNPAID_CANCEL / WDT 属于"可取消"类型：截单成功后会继续走取消链路把订单置为已取消。

## 流程总览

```text
平台订单 → openapi 采集(Mongo) → MQ(orderSendInput) → 平台解析器 → saveOrUpdateOrder
  ├─ 新单：保存为草稿(或按平台状态直接 已取消/待审核/已发货)
  └─ 旧单：版本/终态/人工单校验 → 判断变更 → 截单(按需) → 更新信息

草稿自动提交(autoSubmitJob)：混仓拆单 → 自动分仓 → 提交 → 待审核
待审核 → 自动审单(autoAuditJob)/人工审单：平台状态校验 → SKU映射 → 虚拟单直发 → 生成发货通知单 → 占用库存 → 待发货
待发货 → 合单(mergeJob) → 推仓(pushToWarehouseJob) → 三方仓发货回传/手动标发 → 已发货 → 平台标发(标发MQ) → 签收 → 已完成
截单：任意可截状态 → 订单级截单 或 发货通知单级截单(先取消三方仓出库单) → 问题件/已取消 + 释放库存
RMA：平台同步/手动创建 → 草稿 → 提交 → 审核 → 生成子流程(退款/退货/重发) → 全部完成/取消 → RMA 完成/取消
```

## 与其它模块的关系

- **openapi 服务**：订单原始数据存 Mongo，SMS 通过 `RemoteOpenapiService` 查询；标发（签收申报）也经 openapi 调平台；第三方仓推单/取消/查询走 `RemoteOpenapiWhService`。
- **WMS**：审单占用库存（`occupyInventory`，业务类型 ORDER_BOOKING）、发货扣减（`addOutbound`，SALE_ORDER_OUTBOUND）、截单/取消释放（`releaseInventory`，ORDER_RELEASE）；锁库存查店铺私有库存（`getInventoryByShopId`）。
- **PMS**：查 SKU/商品信息（虚拟品判断、盲盒组合品判断）。
- **并发控制**：订单维度 Redis 锁 `ORDER_LOCK_KEY+orderId`、发货通知单维度 `SHIP_ORDER_LOCK_KEY+shipId`；拉单按店铺+原单号加 `ORDER_PULL_LOCK_KEY`。
