# 订单审核与库存锁定流程

> 代码依据：`chain/order/audit/*`、`AutoAuditRuleServiceImpl`、`OrderLockServiceImpl`、`OrderServiceImpl.audit/lock/unlock/removeLock`。

## 一、审单入口

- **人工审单**：界面批量审单 `audit(OrderAuditReq)`，对每个订单构造 `AuditContext` 串行执行审单责任链；
- **自动审单**：`autoAuditJobHandler` 定时任务 → `AutoAuditRuleServiceImpl.autoAudit()`；
- 两者最终都走同一条 `AuditChain` 责任链，且都持有 `ORDER_LOCK_KEY+orderId` 的 Redis 锁（整个审单链在锁内执行）。

## 二、审单责任链（AuditChain，按 @Order 顺序）

### A. 前置校验（PreAudit）
- 加载订单全量信息（needAll）；
- **状态边界**：只有 待审核/问题件 可审（`canAudit`），否则返回"该状态不能审核"；
- **发货方式边界**：只有直发单（OWN_SEND）支持审单；
- **锁单边界**：订单已锁库存时，若审单参数里指定了仓库且与原仓库不一致 → 拒绝："订单已锁单，审单不允许选择和订单仓库不一样的仓库"。

### B. 平台状态校验（ExtStatusAudit）
- 线下单、人工单跳过校验；
- 按平台加载解析器，从 Mongo 查该原单号的最新完整订单；查不到则放行；
- 用最新数据计算截单类型（`calCutType`）：若平台已退款/取消等 → 审单结果置为问题件（WRONG），并立即发起对应类型的截单，链路终止。

### C. 审单落库（AuditOrder）
- 若前面已得出失败结果 → 终止；
- 成功：更新订单为 **待发货**，写审单时间；审单参数可覆盖快递方式/仓库；
- 清除标签：平台信息更新、退款中、部分退款、退款完成、未付款取消、仓储物流异常；
- 记录"中台订单审核成功"日志；刷新 RMA 重发单状态。

### D. SKU 映射校验（SellerSkuAudit）
- `maintainSellerSku`：按 平台+店铺+sellerSku 维护映射，生成/刷新系统 SKU 明细（OrderItemSon）；
- 映射不完整 → 失败："订单sku缺少映射关系，请维护！"；
- 系统 SKU 明细为空 → 失败："订单缺少sku，请维护！"。

### E. 虚拟订单处理（VirtualOrder）
- 所有系统 SKU 都是虚拟品（SkuType=VIRTUAL_PRODUCT）→ 订单直接置 **已发货**，不生成发货通知单、不占库存、终止链路。

### F. 生成发货通知单（CreateShipping）
- `orderShipService.createOrderShip(orderId)`（详见 [[发货通知与标发流程]]）。

### G. 库存占用（InventoryAudit）
- **已锁单的订单**：
  - 锁定明细全部占用成功（`lockSuccess`：每个 SKU 已锁数=应锁数）→ `removeLock`（清锁定明细、lockFlag=N，保留 lockTime）审单通过；
  - 未占满 → 审单失败转 **问题件**："订单锁定库存占用库存，库存不足"。
- **未锁单的订单**（虚拟品明细跳过）：
  - 组装占用请求：业务类型=ORDER_BOOKING（订单预留），单号=订单号；
  - 仓库若为"非一体化仓"（integrated=0）→ 先同步库存校验 `checkSyncInventory`，不通过转问题件；
  - 调 WMS `occupyInventory` 占用逻辑库存；
  - 任何异常 → 回滚当前事务 → 转问题件 → 事务提交后再发起 `AUDIT_INVENTORY` 类型截单（新事务）。

### 审单结果汇总
| 结果 | 订单状态 |
| --- | --- |
| 成功（实物） | 待发货，生成发货通知单，占用库存 |
| 成功（纯虚拟） | 已发货 |
| 平台状态异常 | 问题件 + 按平台状态截单 |
| SKU 映射缺失 | 保持原状态，返回错误信息 |
| 库存不足/占用失败 | 问题件 + AUDIT_INVENTORY 截单 |

## 三、自动审单（autoAudit）

**任务形态**：`autoAuditJobHandler` 抢全局锁 `ORDER_AUDIT_LOCK_KEY` 后执行。

**候选订单**（每轮最多 100 条，按创建时间倒序）：
- 状态=待审核；发货方式=直发；来源=线上订单；仓库非空。

**单条处理**：
1. 加订单锁（占用则抛异常跳过）；
2. 非直发单跳过；先 `maintainSellerSku` 维护映射，失败记日志退出；
3. 状态必须仍是待审核、仓库非空；
4. 取 **店铺+仓库** 维度的启用中自动审单规则（`AutoAuditRule` 的 shopId 是多店铺逗号分隔，按 "shopId-仓库" 建索引）；
5. 逐条规则项（`AutoRuleItem`）用对应 `RuleHandle` 匹配：
   - 规则项类型：平台、店铺、国家码、省、市、收件国家、SKU、SKU 数量、SKU 总数、库存、运费等（`handler/order/rule`）；
   - 任一规则不匹配 → 记"匹配自动审单规则失败"日志并终止该单；
   - 规则处理类不存在 → 跳过该规则项；
6. 全部通过 → 以订单当前仓库构造 `AuditContext` 走审单链（与人工审单同一链路），记"匹配自动审单规则成功"。

**边界**：自动审单异常只记日志不中断整批；每单独立加锁，避免与人工操作冲突。

## 四、库存锁定（锁单）

锁单=为待审核/问题件订单提前排队占用库存，占用按锁单时间先后顺序执行。

### 手动锁单（lock）
前置校验（任一不满足即报错）：
- 状态 ∈ {待审核, 问题件}（`canLock`）；
- 必须是直发单；
- 必须有仓库；
- 未锁定（lockFlag != Y）；
- 无锁定明细（防止重复锁定）；
- sellerSku 映射完整（`judgeSellerSkuMapOk`）；
- 不含盲盒/组合品（`judgeContainsMh`：明细映射到的商品存在组合品 M 型则拒绝）。

通过后：生成锁定明细（按 SKU 汇总数量，应锁=总量、已锁=0、未锁=总量；沿用已有 lockTime 否则取当前时间），订单置 lockFlag=Y 并记录 lockTime。
虚拟 SKU 不参与锁定；纯虚拟订单禁止锁单。

### 自动锁单任务（autoLockJobHandler → lockJob）
- 抢全局锁 `ORDER_AUTO_LOCK_KEY`；
- 查出所有 未锁数量>0 的锁定明细，**按 lockTime 升序**逐条占用：
  1. 加明细级锁 `ORDER_LOCK_Lock_+id`；
  2. 查 WMS 店铺私有库存（`getInventoryByShopId`：仓库+SKU+店铺）的可用量；查询失败/为空/可用量<=0 → 跳过等下轮；
  3. 本次占用量 = min(可用量, 未锁数量)；
  4. 调 WMS `occupyInventory`（业务类型 ORDER_BOOKING，单号=订单号）；
  5. 更新锁定明细：已锁 += 本次量，未锁 -= 本次量。
- 单条异常不影响其它明细。

### 解锁（unlock）
- 状态必须 ∈ {待审核, 问题件}；必须处于锁定中；
- lockFlag=N；`removeLockTime=true` 时把 lockTime 置空（彻底放弃排队位置）；
- 删除锁定明细；只要历史已锁过（任一明细已锁>0）→ 调 WMS `releaseInventory`（ORDER_RELEASE）释放占用。

### 审单成功移除锁定（removeLock）
- 锁单后审单成功且库存已占满：删除锁定明细、lockFlag=N，但 **保留 lockTime**（后续换货改单重新锁定时沿用排队位置）。

### 改单与锁定的联动
- 待审核/问题件的锁定订单发生 SKU 变更：先 `unlock(id, false)`（释放占用但保留 lockTime）→ 更新明细 → 因 lockTime 存在自动重新 `lock`（重新排队，占用已释放的部分重新竞争）。
- 待发货订单被截单：截单成功释放库存（ORDER_RELEASE）；若截单前锁过单且截单类型为 合单影响/手动截单 → 重新进入锁定排队。

## 五、并发与边界汇总

- 所有订单级写操作（提交、审单、取消、截单、拆单、锁/解锁、标发）统一使用 `ORDER_LOCK_KEY+orderId` Redis 锁，tryLock 失败提示"全局锁被占用，请稍后再试"；
- 自动审单/自动锁单/自动提交任务之间用各自的全局任务锁防止重入；
- 审单失败不会把订单改为已取消（除平台状态=退款完成/未付款取消走截单→取消外），多数失败落点是问题件，等待人工处理。
