# B 端订单（ToB / PI 单）流程

> 代码依据：`TobOrderServiceImpl`、`job/TobOrderJobHandler`、`TobOrderStatusEnums`。

## 一、状态机（TobOrderStatusEnums）

| code | 状态 |
| --- | --- |
| 1 | 草稿 |
| 2 | 待审核 |
| 3 | 待发货 |
| 4 | 部分发货 |
| 5 | 已发货 |
| 6 | 已取消 |

## 二、流程步骤

### 1. 新增（add）
- 校验：平台、店铺、产品明细必填；
- 单号前缀 **PI**（6 位序列）；初始状态=草稿；
- 保存主单 + 地址 + 明细。

### 2. 编辑（edit）
- 加 `TO_B_ORDER_LOCK_+orderId` 锁；
- 明细整批删除重建；地址更新。

### 3. 提交（submit）
- 加锁；状态 草稿→待审核；记提交日志。

### 4. 审核（audit）——B 端单转 C 端单
- 加锁；审核通过时：
  1. 按 B 端订单明细生成对应 **C 端销售订单**（订单属性=4 B 端正常销售订单），含系统 SKU 明细、地址、费用（总费用=成交额、支付状态=已支付、收款账户）；
  2. B 端单状态 → **待发货**；
  3. 记审核日志。
- 之后 C 端单走销售订单正常链路（审单/发货），其发货状态聚合回写 B 端单（部分发货/已发货）。

### 5. 标记付款（markPaid）
- 边界：仅 **草稿 且 未支付** 可标记；
- 支付状态改为已支付。

### 6. 删除（delete）
- 逻辑删除（delFlag=1）。

### 7. 整单关闭（cancel）
- 加锁；
- **状态边界**：`canCancel`（草稿/待审核/待发货）；
- 待审核 → 直接关闭；
- **待发货 → 必须其生成的所有 C 端订单全部已取消**，否则报"当前订单：xxx 存在未取消的C端订单"；
- 状态置已取消，记关闭日志。

## 三、边界汇总

- B 端单与 C 端单是父子关系：B 端审核生成 C 端单，B 端关闭受 C 端单状态约束；
- C 端单属性=4，参与正常审单发货，但不参与自动合单（合单只收属性=1）；
- 支付状态只有 未支付/已支付/货到付款 三种（PayStatusEnums），B 端单默认审核后即已支付；
- 所有操作均加订单级 Redis 锁，防止并发修改。
