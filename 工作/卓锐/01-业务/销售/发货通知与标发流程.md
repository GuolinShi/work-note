# 发货通知与标发流程

> 代码依据：`OrderShipServiceImpl`、`chain/order/send/*`、`mq/SignOrderService`、`job/OrderShipJobHandler`。

## 一、发货通知单生成（createOrderShip）

审单链 F 步骤调用，也可单独触发：
- **前置**：
  - 过滤虚拟品后明细为空 → 不生成（纯虚拟订单）；
  - 非鲸汇单：订单状态必须是 **待发货**，否则不生成；
  - 订单已有发货通知单号 → 不重复生成。
- **生成内容**：
  - 单号：序列号前缀 `SALES_ORDER_SHIP_PRE`；
  - sourceNoList=订单号（合单后为多个逗号拼接），订单数=1；
  - 状态=待发货；明细按系统 SKU 汇总；地址复制订单地址；
  - **仓库对接判定**：查订单仓库的 `integrated` 字段：
    - 非一体化仓（integrated != 0，即未对接三方仓）→ pushFlag=**无需推送**（后续走手动标发）；
    - 一体化仓 → pushFlag=未推送（等待推仓任务）。
- 回写订单的发货通知单号。

## 二、推送三方仓（PushToWarehouseJobHandler → pushToWarehouse）

**前置校验**（加 `SHIP_ORDER_LOCK_KEY+shipId` 锁）：
- 状态必须是待发货，否则"不是待发货，不能推送"；
- pushFlag 必须是未推送，否则"已推送，请勿重推"；
- 仓库单号必须为空，否则"仓库单号不为空，不能推送"。

**推送内容**：店铺、加急标识、通知单号作为 referenceNo、运输方式、平台、平台单号、备注、收件人全量地址、SKU+数量；经 `RemoteOpenapiWhService.createOutbound` 推送到对应三方仓（按仓库维度路由）。

**结果处理**：
- openapi 服务不可用（resp=null）→ 本次跳过，下轮重试；
- 服务间异常 → 记日志；三方系统返回错误 → 发货通知单截单（类型 PUSH_EXT_WAREHOUSE），订单转问题件；
- 成功 → pushFlag=已推送，记录三方仓返回的仓库单号（warehouseNo）。

## 三、同步三方仓状态（SyncFromWarehouseJobHandler → syncFromWarehouse）

定时轮询已推送的通知单，从三方仓查出库单最新状态并回写：
- 三方仓 **已发货** → 通知单置已发货，回写运单号/快递/发货时间，并联动所有源订单发货（走发货链）；
- 三方仓 **问题件/异常** → 系统截单（类型 SYNC_EXT_WAREHOUSE），订单转问题件；
- 其它状态（拣货中/打包中等）→ 只更新中间状态。

## 四、发货（send）

入口：三方仓状态回传（自动）、手动标发（界面）。加通知单锁。

**前置**：通知单必须是待发货。
- **手动标发**（界面）：
  - 仓库单号必须为空（未对接仓库的单才能手动标发）；
  - pushFlag 必须是无需推送；
  - 否则分别报"仓库单号不为空，不能手动标记发货"/"已对接仓库，不能手动标记发货"。
- **自动发货**（三方仓回传）：
  - 仓库单号必须非空；
  - pushFlag 不能是未推送（必须先推过仓）。

**发货链（SendChain，订单维度逐个执行，每个订单加订单锁）**：
1. A 前置：订单状态必须是 **待发货**（`canSend`），否则抛"订单状态不支持发货"；
2. B 发货（doSend）：订单写运单号、快递方式、发货时间、仓库单号，状态置 **已发货**，记"订单发货"日志，刷新 RMA 重发状态；
3. C 扣库存：实物明细调 WMS `addOutbound`（业务类型 SALE_ORDER_OUTBOUND）扣减库存并生成出库流水（虚拟品跳过）；
4. D 后置：事务提交后发标发 MQ（`sendSignMsg`）。

## 五、平台标发（SignOrderService）

标发=把发货信息（运单号+物流渠道）申报回销售平台。

**生产者**：发货链 D 步骤，事务提交后按订单发 MQ。
**消费者**（`orderSignInput` → `consumeSignMsg`）：
1. 加订单锁；
2. `ignoreSign` 判断（无需标发的场景直接跳过）；
3. 组装标发请求：
   - 按订单快递方式查 WMS `LastLgsChannel`（末端物流渠道）；
   - 再按 渠道+平台 查 `LastLgsChannelMapping` 得到平台侧物流编码；
   - 任一缺失 → 标发失败（"无法找到平台配送方式/映射"）；
4. 调 openapi `sign` 接口向平台申报（含平台明细行：platformItemId、数量、sellerSku、transactionId）；
5. `orderService.sign`：成功 → signFlag=已标发；失败 → 记"订单标发失败"日志并抛异常（MQ 重试）。

## 六、定时任务一览（OrderShipJobHandler）

| 任务 | 作用 | 全局锁 |
| --- | --- | --- |
| SyncFromWarehouseJobHandler | 同步三方仓出库单状态，驱动发货/截单 | 通知单级锁 |
| PushToWarehouseJobHandler | 批量推送未推送的待发货通知单 | 通知单级锁 |
| MergeShipJobHandler | 自动合单 | 通知单 MultiLock |

## 七、发货通知单状态机（OrderShipStatusEnums）

0 待发货 → 1 已发货；0 待发货 → 2 已取消（截单成功/合单作废）。

## 八、边界汇总

- 通知单只在订单=待发货时生成；一个订单同一时间只有一张有效通知单（合单后旧单作废、新单生效）；
- 推仓三要素：待发货 + 未推送 + 仓库单号为空，缺一不能推；
- 手动标发仅用于未对接仓库（pushFlag=无需推送）的单；已对接仓库的单必须由三方仓回传发货；
- 发货必扣库存（实物）；扣库存与订单状态更新不在同一分布式事务内，靠业务类型+单号幂等；
- 标发失败依赖 MQ 重试，不影响订单已发货状态。
