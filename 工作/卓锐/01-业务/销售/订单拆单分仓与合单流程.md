# 订单拆单分仓与合单流程

> 代码依据：`handler/order/split/*`、`AutoWhRuleServiceImpl`、`OrderShipServiceImpl.merge/doMergeOrder`。

## 一、拆单总览

拆单发生在 **订单（Order）层面**，三种策略：

| 策略 | 触发方式 | 场景 |
| --- | --- | --- |
| WarehouseSplitStrategy | 自动（自动提交 MIXED_SPLIT 步骤） | 混仓单拆成 自发子单 + 代发子单 |
| AutoSplitStrategy | 自动（提交后 autoSplitAndAllocateWarehouse） | 按数量/规则把一单拆成多个子单 |
| ManualSplitStrategy | 界面手动拆单 | 人工指定每个子单的明细 |

### 拆单公共边界（AbstractSplitStrategy.split）
1. 加 `ORDER_LOCK_KEY+orderId` 锁，占用则报"全局锁被占用"；
2. **状态边界**：只有 草稿/待审核/问题件（`canSplit`）可拆；
3. 手动/自动拆单入口额外校验：lockFlag=Y（已锁库存）不允许拆单；
4. 拆出的子单数量必须 >1，否则报"拆出来的子单数量<=1"；
5. 核心拆单逻辑（coreSplit）：
   - 生成新订单号；复制主单/地址/费用；
   - 明细数量分摊：按 sellerSku→SKU 的数量比例拆，最后一个子单用减法兜底，防止精度丢失；
   - 费用分摊：订单费用与 SKU 费用同样按比例分摊，最后一个子单取剩余值；
   - 校验：拆完后 sellerSku 数量、SKU 数量、成交额必须与原单一致，否则分别报"数量拆错/成交额拆错"并终止；
   - SKU 数量拆成 0 → 报错终止；
6. 拆单完成后（afterSplit）：
   - 原单若还有剩余数量 → 回写原单；若无剩余 → **取消原单**（拆单取消标签 SPLIT_CANCEL，取消类型=拆单取消）；
   - 子单打拆单相关标签；
   - RMA 重发单拆单时同步更新重发单的展示单号。
7. 混仓拆单（WarehouseSplitStrategy）特有：
   - 自发 SKU → 自发子单，step=AUTO_WH（继续自动分仓）；
   - 代发 SKU → 代发子单，step=SUBMIT，仓库=店铺默认仓；
   - 拆单内容记"自动拆分订单，新增自发/代发订单"。

### 自动拆单（autoSplit，提交后触发）
- 入口条件：`order.isNeedSplit()` 为真；已锁单禁止；
- 明细为空不拆；只有一个明细且数量<=1 不拆；
- 按明细逐件组装拆单请求后走手动拆单同一套核心逻辑。

## 二、自动分仓（AutoWhRule）

- 时机：自动提交的 AUTO_WH 步骤、人工提交后、自动拆单后；
- `autoWh(orderCode)`：按自动分仓规则（`AutoWhRule`）匹配订单，命中则返回 仓库+快递方式；
- 命中：写仓库、仓库名、快递方式，记"自动分仓成功，分配仓库xx"；
- 未命中：记"自动分仓失败"日志，订单保持无仓库（需人工指派，审单时人工选仓）；
- 订单已指定仓库（人工指定）→ 记"已指定仓库不参与自动分仓"，不覆盖。

## 三、合单（发货通知单层面）

合单发生在 **发货通知单（OrderShip）层面**，即多张通知单合成一张再推仓。

### 自动合单（MergeShipJobHandler → merge）
1. 候选：状态=待发货、mergeFlag=未执行合单、订单属性=**C 端正常销售订单（属性 1）** 的发货通知单；
2. **第一步分组**（相同才可能合并）：平台 + 仓库 + 店铺 + 订单属性 + 加急标识 + 快递方式；
3. **第二步分组**：收件地址完全相同（收件人、公司、国家码、邮箱、客户名、省、市、邮编、电话、地址1、地址2、门牌号全部拼接比较）；
4. 每组执行 `doMergeOrder`。

### 合单执行（doMergeOrder）
- 加多单联锁（所有参与船单各自的 `SHIP_ORDER_LOCK_KEY` 组成 MultiLock），tryLock 失败报"合单单据正在处理中,请稍后重试"；
- **前置校验**：参与合并的单必须全部满足 状态=待发货 且 pushFlag=未推送，否则报"存在单据不满足合单条件"；
- 只有 1 张单 → 仅把 mergeFlag 置为已执行合单，不产生新单；
- 多张单：
  1. 生成新发货通知单（新单号），sourceNoList=所有源单号逗号拼接，订单数=源单数，mergeFlag=是，加急/推送标志取第一张；
  2. 地址取第一张单的地址；
  3. 明细按 SKU 汇总数量；
  4. 保存新单（主单+地址+明细）；
  5. 原单全部置 **已取消**，并置 mergeFlag=已执行；
  6. 回写所有源订单的发货通知单号为新单号。
- 异常 → 事务回滚。

### 合单与截单的联动（重要边界）
- 合单后的任一源订单发生平台更新/退款 → 截单类型为 **MERGE_AFFECT（合单影响）**，整张合并通知单走截单，其它受影响的源订单也会被连带截单（见 [[截单与取消流程]]）。

## 四、边界汇总

- 拆单只允许发货前（草稿/待审核/问题件），锁单后禁止；
- 拆单保证数量与金额守恒（拆错即报错终止，事务回滚）；
- 自动合单只针对 C 端正常销售单；已推仓（pushFlag != 未推送）或已发货的通知单不参与合单；
- 合单不改订单状态，只改发货通知单结构；源订单仍各自独立流转（截单/取消会互相影响）。
