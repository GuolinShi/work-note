# 退货与退运流程

> 代码依据：`ReturnServiceImpl`、`ReturnOnroadServiceImpl`、`chain/return_*`、`job/ReturnJobHandler`。
> 两条链路：**退件**（客户/物流退回的散件，经质检后入库）与 **在途退运**（已发货未签收的整箱货物中途退回）。

## 一、退件单（Return）

### 1. 状态机（ReturnStatusEnum）

1 待提交 → 2 待质检 → 3 待入库 → 4 已完成；5 已作废。
辅助状态：
- 推送状态（ReturnPushStatusEnum）：1 未推送第三方仓 / 2 已推送 / -1 推送失败（预报三方仓入库用）；
- 入库状态（ReturnInboundStatusEnum）：0 未入库 / 1 入库中 / 2 入库失败。

### 2. 创建（saveReturn）
- 来源：RMA 同步（ReturnSourceEnum.RMA，SMS 审核通过后推送）或手动导入（OTHER）；
- 类型（ReturnTypeEnum）：客户退件 / 物流退件；
- 校验：来源必填；明细 SKU 必须存在于 PMS 商品库（`perfectSku`，不存在报"sku不存在"）；
- 生成退件单号（前缀 SALES_RMA_RETURN_PRE），初始：待提交 + 未推送 + 未入库。

### 3. 提交（submit）
- 加退件锁；状态 待提交→待质检；回写 SMS RMA 退货状态。

### 4. 质检（quality）
- 录入每个明细的 **收货数** 与 **良品数**（必须录入良品数，否则报"请录入退件良品数"）；
- 不良品数 = 收货数 - 良品数（自动计算）；
- 回写 SMS（`updateReturnInfo`：RMA 退货行快照更新 实收/良品/不良品）；回写 RMA 退货状态。

### 5. 收货入库（inboundReceive）——责任链（InboundReceiveChain）
加退件锁后执行：
1. **A 前置校验**：入库时间默认当前；至少一行收货数>0，否则报"总入库数量为0不允许收货入库"；退件状态必须是 **待入库**，否则报"退件状态不是待入库"；
2. **B 回写入库**：回写上游（顺丰/菜鸟等）入库成功（TODO 占位）；
3. **C SKU 入库信息**：整理 SKU 入库明细（当前不支持分批入库）；
4. **D 退件单入库**：退件单状态→已完成，更新上下文；
5. **E 库存入库**：构建退货入库单（业务类型 RETURN_INBOUND，入库仓=退件仓，源单号=来源单号），**入库数量=良品数**，货权层级=退件单指定层级（不良品不入可用库存），调 `addInbound`。

完成后回写入库单号/入库时间；入库单号非空→入库中（成功），否则入库失败；最后回写 RMA 退货状态。

### 6. 第三方仓预报（createInbound / queryInbound 任务）
- 待提交且需推三方仓的退件单 → 调三方仓创建入库单（回写跟踪号等，推送状态=已推送，状态→待收货类中间态）；
- `queryInbound` 轮询三方仓入库进度回写。

### 7. 取消（cancel）/确认入库（confirmInbound）
- 取消：按状态边界把退件单置已作废（联动取消未完成的入库）；
- 确认入库：人工确认入库结果后收尾。

## 二、在途退运（ReturnOnroad）

针对 **已发货** 的调拨发货单，把未签收的整箱货退运回指定仓库：

### 创建边界（createReturnOnroad）
- 来源发货单必填、退运明细必填、退运数量必须 >0；
- **发货单必须=已发货状态**，否则报"只有已发货状态的单据才能发起退运"；
- 发货单正在处理退运（并发锁）→ 拒绝；
- 每行：发货明细必须存在；**退运数量 ≤ 可退运数量**（发货数-已收-已退运），超出报"可退运数量为x，退运数量不能超过x"；
- **仅支持整箱退运**：退运数量必须是单箱数量的整数倍，否则报"必须是单箱数量x的整数倍"。

### 执行（创建即执行）
1. 加库存操作锁；
2. **退运出库**（业务类型 RETURN_ONROAD_OUTBOUND，-8）：目的仓扣减在途/相关库存（服务未注册报"退运出库服务未注册"）；
3. **退运入库**（业务类型 RETURN_ONROAD_INBOUND，8）：退运仓增加可用库存；
4. 生成退运单与明细，回写发货明细已退运数量与箱状态（已退运）。

## 三、与 SMS/RMA 的联动

- RMA 审核通过后由 SMS 调 `saveReturn` 创建退件单（来源=RMA，携带退货仓/跟踪号/货权层级/产品快照）；
- 退件质检与入库结果通过 `remoteSmsService.updateReturnInfo/updateReturnStatus` 回写 SMS；
- SMS 侧 RMA 完成判定依赖所有退货行的退件单到达终态。

## 四、边界汇总

- 退件入库数量=良品数；不良品不进可用库存（留在不良品口径）；
- 退件入库前必须完成质检（状态必须待入库）；
- 在途退运只针对已发货单、只支持整箱、不能超可退运量；
- 退运出库+入库在同一流程内完成，无中间单据状态（创建即执行）；
- 退件单与收货单共用退件/收货锁体系，防止并发重复入库。
