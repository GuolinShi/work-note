# 发货与出库流程

> 代码依据：`DeliveryPlanServiceImpl`、`LogisticsPlanBachServiceImpl`、`AllocateServiceImpl`、`ShipmentServiceImpl`、`job/ShipmentJobHandler`。
> 头程发货链路：交货计划 → 物流计划批次 → 调拨计划 → 调拨发货单 → 出库/推三方仓 → 收货。

## 一、交货计划（DeliveryPlan）

状态机：1 草稿 → 2 待采购确认 → 3 待物控确认 → 4 已确认。
- 提交（submit）：仅草稿可提交，置待采购确认；
- 确认（confirm，confirmType=1 采购确认 / 2 物控确认）：
  - 状态必须匹配（待采购确认/待物控确认），否则报"非xx状态不允许确认"；
  - 明细校验：每个 SKU 必须有单箱数量（ProductBox.boxPcs），确认数量必须是整箱倍数，否则报"SKU[x]，非整箱发货，请先确认！"；
  - 采购确认用"采购建议数量"，物控确认用"计划数量"；
  - 重算计划发货总数与未下达数。
- 已确认后，物流计划批次从交货计划明细"下达"数量（releasedQty），删除批次时回退（`subReleasedQty`）。

## 二、物流计划批次（LogisticsPlanBach）

状态机：WAIT_COMMIT 草稿 → WAIT_AUDIT 待审核 → FINISH_AUDIT 已审核 → EXECUTING 执行中 → FINISHED 已完成 / CLOSED 已关闭 / 已作废。

- **提交（commit）**：仅草稿可提交 → 待审核；
- **审核（audit）**：仅待审核可审核；
  - 通过 → 已审核，并立即 `allocateService.createAllocateByLogisticPlan` **生成调拨计划**；
  - 拒绝（必须填原因）→ 退回草稿；
  - 审核后 `recalculateLogisticsPlan` 重算批次执行进度；
- **反审核（converseAudit）**：仅已审核可反审核，且 **不能已关联调拨计划**，否则报"该物流批次计划已关联调拨计划"；
- **删除（remove）**：仅草稿/已关闭可删除；非 FBA 批次删除时回退交货计划已下达数量；
- **关闭（close）**/作废：终止批次；
- 发货单发货/截单后 `updateStatusByShipment` 会重算关联批次状态（执行中/已完成）。

## 三、调拨计划（Allocate）

状态机：0 待推单 → -1 已推单（审核中）→ 1 已推单（审核通过）。

- **提交/推单（submit）**：仅待推单可提交；校验明细的目的仓三方 SKU 必填；发起钉钉审批流；状态→已推单（审核中）；
- **审核（audit，钉钉回调/界面）**：仅待审核可审核；通过→已推单；拒绝→待推单；
- **反审核（converseAudit）**：仅已推单可反审核，且 **不能存在关联发货单**；
- **生成发货单（createShipmentByAllocate）**：见下节；
- 发货单截单后若调拨计划下已无任何发货单 → 自动回退待推单（`resetAllocateToWaitPush`）。

## 四、调拨发货单（Shipment）生命周期

状态机（ShipmentStatusEnum）：0 草稿 → 1 待审核 → 2 待发货 → 3 已发货（待收货）。
推送状态（ShipPushStatusEnum）：0 未推送 / 1 推送成功 / 2 推送失败 / 3 无需推送。

### 1. 生成发货单（createShipmentByAllocate）
加调拨计划锁；校验：
- 明细、入库类型、调拨计划必填；
- 始发仓为已对接三方仓时，物流渠道必填；
- 每个 SKU：商品存在；始发仓/目的仓有三方仓账号时对应三方 SKU 必填；**包装单箱数量必填，且发货数量必须是单箱数量的整数倍且 >0**；
- FBA 调拨：发货数量不能超过计划数量；
- 按字典 `wms_not_push_warehouse` 判断是否"无需推送"；
- 生成发货单（草稿）+明细+箱信息。

### 2. 提交（submit）
- 仅草稿可提交；发起钉钉审批流；状态→待审核；（提交不占库存）。

### 3. 审核（audit）
- 仅待审核可审核；
- **通过**：
  - 命中"自动质检入库"配置的单据先做自动处理（`doAutoQcInAndAdjust`）；
  - 状态→待发货；
  - **占用库存**（头程发货锁定 SHIPMENT_BOOKING，按始发仓可用库存；库存不足则审核失败回滚）；
- **拒绝**：状态回草稿。

### 4. 发货（shipping，手动）
- 仅待发货（或无需推送）可发货；
- **物流费用校验**：领星调拨单类单据发货前强制校验费用（费用不可修改），未确认费用需显式确认（feeZeroConfirmed）；
- **装箱信息必填**；
- 始发仓执行 **调拨出库**（SHIPMENT_OUTBOUND，addOutbound 直接出库，走批次 FIFO；批次转入目的仓在途）；
- 状态→已发货；重算物流计划批次状态。

### 5. 推送三方仓出库（createOutboundJob → createOutbound）
- 待发货且未推送、始发仓已对接的发货单推送三方仓创建出库单（referenceNo=发货单号）；
- 成功：推送状态=成功，记录三方仓出库单号（outboundNo）；
- 失败：推送状态=失败，记日志；
- `queryOutboundJob → afterQueryOutbound`：同步三方仓出库状态（出库完成等）回写发货单。

### 6. 截单/取消（cancel）
- **仅待发货状态可截单**，否则报"审核状态非待发货不能截单"；
- 已推送三方仓出库单 → 先调三方仓取消接口，失败则整体报"取消出库单失败"中止；
- 清空推送状态/出库单号/运单号；
- **释放库存**（头程发货释放）；删除明细与箱子；删除发货单；
- 回写物流计划批次（重算）；调拨计划回退待推单（若无其它发货单）。

### 7. 批量操作
- batchSubmit / batchAudit / batchSend / batchDelete / batchPushToThirdWh：逐单执行上述逻辑并汇总成功/失败原因；调拨计划来源的批量审核 `batchAuditForAllocate` 单独入口。

## 五、出库通用流程（AbstractOutboundServiceImpl）

见 [[库存]] 第四节。发货链路相关要点：
- 调拨出库用 **直接出库**（审核时已占用则走锁定出库，具体由实现类决定）；
- 调拨出库产生 **目的仓批次在途**，收货入库时核销；
- 出库扣减顺序：批次 → 私有可用 → 总账，任一不足即整体失败回滚。

## 六、边界汇总

| 环节 | 关键边界 |
| --- | --- |
| 交货计划确认 | 数量必须整箱；状态必须逐级确认 |
| 物流批次 | 已关联调拨计划不能反审核；草稿/已关闭才能删除 |
| 调拨计划 | 有发货单不能反审核；发货单全截单后自动回退待推单 |
| 生成发货单 | 发货数量为单箱整数倍；FBA 不超计划量；三方仓 SKU 映射必填 |
| 审核 | 通过即占用始发仓库存；库存不足审核失败 |
| 发货 | 装箱必填；领星调拨单费用必须校验 |
| 截单 | 仅待发货；已推仓需先取消三方仓出库单；截单释放库存并回退上游单据 |
