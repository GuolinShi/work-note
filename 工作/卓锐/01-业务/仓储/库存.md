# 库存

> 代码依据：`InventoryServiceImpl`、`InventoryPrivateLogServiceImpl`、`AbstractOccupyServiceImpl`/`OccupyTrxServiceImpl`、`AbstractReleaseServiceImpl`、`AbstractInboundServiceImpl`、`AbstractOutboundServiceImpl`、`InventoryBatchServiceImpl`、`InventoryAssignServiceImpl`、`InventorySnapshotHandler`。

## 一、账目结构

- **总账 Inventory**：仓库+SKU 唯一；字段含可用/锁定/采购在途/调拨在途/不良品/待上架/样品/二手；更新用 `getInventoryForUpdate`（行锁）。
- **私有库存 InventoryPrivate**：仓库+SKU+货权层级（privateId）唯一，字段同总账；所有出入库先落私有账再汇总总账。
- **库存层级 InventoryLevel**：货权树；公共层级（parentId=0）不可删除。店铺通过 `InventoryLevelShop` 绑定层级扣减优先顺序。
- **批次 InventoryBatch**：入库按业务类型决定是否新建批次（`isNewBatch`）；出库按策略扣减批次（默认 FIFO）；调拨出库把批次转入 **批次在途 InventoryBatchOnroad**（目的仓维度），调拨入库时核销在途。
- **锁定 InventoryLock**：占用产生的锁定明细，按 业务类型+业务单号+锁定批次（lockBatch） 索引，是"锁定出库"和"释放"的核销依据。
- **日志**：总账变化日志 `InventoryAllLog`、私有账日志 `InventoryPrivateLog`、批次记录 `InventoryBatchRecord`；另有全量日志查询视图（InventoryAllLogController）。

## 二、占用库存（occupyInventory）

入口：`OccupyTypeFactory.getOccupyType(OccupyTypeEnum).occupyInventory(vo)`。
业务对：订单锁定(-200→-4 销售出库)、头程发货锁定(-300→-3 调拨出库)、其他出库锁定(-400→-100)、盘点出库锁定(-500→-2)、采购调整锁定(-700→-7)。

流程：
1. 按仓库加可用量锁 `INVENTORY_AVAILABLE_LOCK_KEY+whId`（tryLock 等待 60s、持有 120s；拿不到报"预占库存失败，系统繁忙请稍后再试！"）；
2. 参数校验：仓库非空；业务类型必须是负数编码且 type=lock；明细非空；
3. 独立事务（REPEATABLE_READ，`OccupyTrxServiceImpl`）：
   - `deductInventoryPrivate`：按货权层级扣私有可用（见下）；
   - 总账记两笔：可用减少、锁定增加；私有账同步记日志；
   - 生成 lockBatch（雪花号），写 `InventoryLock` 锁定明细。

### 私有库存扣减规则（deductInventoryPrivate，边界核心）
- 明细未指定 privateId 时：必须提供 shopId，按 **店铺扣减优先顺序**（InventoryLevelShop）依次扣各层级；未维护顺序报"请先维护店铺扣减库存的优先顺序"；
- 汇总可用量 < 出库数量 → 报"仓库【x】、SKU【y】私有可用库存不足，请确认！"；
- 按层级顺序 **逐层扣到够为止**（每层扣 min(剩余需求, 该层可用)）；
- **鲸汇订单例外**（orderFromJh=true）：允许负库存，直接取第一个层级全额扣减（不做可用量校验）；
- 指定 privateId 时：该层可用 < 需求量 → 报不足。
- 私有账可用库存减成负数时报"所选仓库下SKU【x】可用库存不足"；例外：鲸汇订单、其他入库。

## 三、释放库存（releaseInventory）

入口：`ReleaseTypeFactory.getReleaseType(ReleaseTypeEnum).releaseInventory(vo)`。
流程：
1. 校验业务单号、业务类型（正数编码且 type=unlock）；
2. 按 业务类型+业务单号 查锁定明细；**无锁定记录直接返回**（幂等）；
3. 一个业务单号只允许对应一个 lockBatch，否则报"存在多条锁定记录"；
4. 总账/私有账：锁定减少 → 可用增加（四笔流水）；
5. 删除该单的锁定明细。

## 四、出库（addOutbound / addLockOutbound）

**直接出库 addOutbound**（未占用的业务）：
1. 校验：业务类型匹配、仓库非空、编码为负、明细非空；
2. 生成出库单；
3. **扣批次**：按策略（FIFO）扣减 InventoryBatch，不足报"所选仓库下SKU【x】可用库存不足"；
4. 调拨出库特有：批次转 **目的仓批次在途**；
5. 扣私有可用（同占用规则，含不足校验）；
6. 扣总账可用，记日志。

**锁定出库 addLockOutbound**（先占用后出库：销售出库、调拨出库、其他出库、盘点出库等）：
1. 按 业务类型(锁定编码)+单号 查锁定明细；**不存在锁定 → 报"单据【x】不存在锁定库存"**；
2. 生成出库单；
3. 扣锁定明细（`deductInventoryLock`）：锁定数量不足报"锁定库存不足"、锁定库存ID为空报错；
4. 扣私有账（按锁定明细的 privateId 精确扣减）；
5. 扣批次（调拨出库转在途）；
6. 扣总账、扩展回调（如调拨出库后更新发货单状态）。

## 五、入库（addInbound）

1. 校验：业务类型匹配、仓库非空、编码为正、明细非空、货权层级必填；
2. 生成入库单（入库时间=当前）；
3. 批次：按业务类型决定 **新建批次** 或 **并入在途/旧批次**（调拨入库核销批次在途）；
4. 总账增加、私有账增加（入库不校验负库存）；
5. 扩展入库（如退货入库回写退件单）。

## 六、库存分配（InventoryAssign）

同一仓库内不同货权层级之间转移 **可用库存**（总账不变）：
- 手工分配：按明细 fromPrivateId→toPrivateId，逐条校验来源层可用 ≥ 分配量（不足报"私有可用库存不足"），出+入两笔私有账流水，业务类型=1000；
- 自动分配（库存调平任务 `inventoryAutoAssign`，业务类型=1100）：
  1. 按仓库加锁（仓库级+全局任务锁）；
  2. 查出该仓所有 **负库存** 的私有账记录，按 SKU 分组；
  3. 该 SKU 全部层级都 ≤0 → 跳过；
  4. 用正库存层级填补负库存层级：总可用 ≤ 总亏空 → 全额摊分；否则 **按正库存比例摊分**；
  5. 生成自动分配单并落账（备注"库存自动调平+uuid"）。

## 七、快照与同步

- **库存快照**：`inventorySnapshotJobHandler` 每日生成 InventorySnapshot（总账）与私有快照（InventoryPrivateSnapshot）；`removeInventoryHistoryJobHandler` 清理历史；
- **三方仓/平台库存同步**：领星/易仓/一全通（Yqn）/Wayfair CG/AmazonFBA 库存定时同步到本地镜像表（各 `*InventoryService` + Snapshot），供对账与可用性参考；
- **库存推送**：`InventorySendListener`（MQ）处理库存下发/同步消息。

## 八、边界汇总

- 所有扣减以 **私有账可用量** 为准，总账由私有账汇总而来；
- 负库存只允许两种入口：鲸汇订单出库、其他入库（其余场景一律拒绝）；
- 占用/释放/锁定出库通过 业务类型+单号 幂等关联；无锁定记录的释放静默返回；
- 批次不足与私有可用不足都会阻断出库（报"可用库存不足"）；
- 占用全程持仓库级 Redis 锁 + 独立事务，避免超卖；
- 调拨链路库存轨迹：始发仓可用 →（出库）始发仓扣减+目的仓批次在途 →（入库）目的仓可用+核销在途。
